## 1. 在 Godot 編輯器開啟與執行

1. 到 <https://godotengine.org/download/archive/4.7.2-stable/> 下載 **Godot 4.7.2 stable（標準版，非 .NET 版）**，解壓即可使用。
2. 開啟 Godot → 「匯入」→ 選這個資料夾裡的 `project.godot`。
3. 第一次開啟會自動匯入字型與圖示（幾秒鐘）。
4. 按右上角 ▶（或 F5）執行。從主選單開始。

> 在編輯器中執行屬於「除錯版」，頂端會出現「除錯」按鈕：選關、+20 金幣、文明 +1 級、直接過關。匯出的正式版不會出現。

## 2. 遊戲操作

備戰時間依回合而定：**第 1 回合 45 秒、第 2～6 回合 30 秒、第 7～18 回合 25 秒、第 19～24 回合 30 秒**（`data/game_config.json → rounds.prep_by_round`）。上一場戰鬥結束、畫面回到備戰後才開始倒數；頂部倒數條剩 10 秒變黃、剩 5 秒變紅並有大字提醒；只有打開選單、除錯面板或放棄確認時暫停（看裝備、合成預覽、三選一都不暫停）。**沒有開始戰鬥按鈕**：倒數歸零自動開戰，上場人數未滿時從候補區最左邊依序自動補上；戰鬥結束後自動進入下一回合。

**戰鬥中可以做的事**：刷新、購買、鎖定商店、買經驗、出售或整理候補區的棋子、查看資訊、替任何棋子（包括正在戰鬥的）穿裝備或合成組件——戰鬥中的棋子穿上後立即生效，已經發生的傷害不會重算。**不能**把棋子換上或移下戰場、不能出售正在戰鬥的棋子；牽涉戰鬥中棋子的升星合成會延到下一回合備戰時完成。

| 動作 | 滑鼠／觸控 | 電腦快捷鍵 |

**特殊裝備獎勵**：第 3、6、9、12、15、18、21 回合戰鬥後（只要遠征生命還在），在**下一回合備戰時**三選一（依敵軍勢力掉落）。選擇時倒數**不暫停**，面板外可以照常操作，也可以「先收起」稍後再選；最後 5 秒有紅色提醒。倒數歸零仍未選擇，會從顯示的三件中隨機發放一件（固定種子），開戰後不能再選。第 24 回合後沒有額外回合。

**基礎組件與合成**：鐵刃（攻擊 +12）、獵弦（攻速 +10%）、鐵甲（物防 +12）、法晶（技能傷害 +12%）、生命石（生命 +150）。一般戰鬥（不含特殊戰鬥與第 24 回合）後有機會掉落，每章至少 2 個、最多 3 個，第 5、11、17、23 回合結束時補足保底。任兩個組件合成一件完整裝備（15 種，只佔一格）。

裝備沒有品質分級、沒有職業限制，每隻棋子 2 格。屬性正常累加；沒有唯一特性的純數值裝備可以自由疊加；同一棋子相同唯一特性只生效一次。合成時保留主體（已上場 → 選中 → 編號小）的裝備，其餘依序補空格、超過 2 件回背包；出售棋子時裝備回背包。

**棋子頭上**：HP／MP 條左側是星級（一點＝一星、兩點＝二星、金星＝三星）；有裝備時條下會出現 1～2 個小圖示。候補區的棋子不顯示 HP／MP，只在頭上顯示星級。

戰鬥播放會自動加速（前 18 秒 0.85×、18–30 秒 1.3×、之後 1.7×），也可再切換 1×／2×／4× 或「略過」（直接算完剩下的戰鬥，結果與正常播放相同）。施放技能前有 0.25 秒前搖、遠程攻擊有飛行時間；攻擊動作、傷害數字停留較 V0.4 更久，陣亡棋子會淡出。

## 3. 自動化檢查（確認沒有載入或解析錯誤）

一鍵執行三個步驟：① 匯入並解析所有腳本 ② 規則／戰鬥自動測試 ③ 實際開啟每個畫面並模擬點擊、拖曳、開戰、存讀檔的冒煙測試。

**Windows**（請用檔名有 `_console` 的 Godot 執行檔，才看得到輸出）：
```bat
tools\check.bat "C:\Godot\Godot_v4.7.2-stable_win64_console.exe"
```
**Linux / macOS**：
```bash
tools/check.sh /path/to/godot
```
最後出現 `✓ 全部檢查通過` 即代表成功；紀錄在 `build/check_*.log`。

也可以單獨執行：
```bash
godot --headless --path . --script res://tests/run_tests.gd        # 規則與戰鬥測試
godot --headless --path . res://tests/smoke_test.tscn              # 畫面冒煙測試
godot --headless --path . --script res://tests/balance_sim.gd -- --runs=20   # 難度模擬報表
godot --headless --path . --script res://tests/strategy_sim.gd -- --runs=6 --out=docs/V0.5_模擬報告.md   # V0.5 三種策略＋抽卡模擬
```
場景 `scenes/game.tscn` 由 `python3 tools/gen_game_scene.py` 產生（改版面時改這個腳本再重新產生）。

測試涵蓋（V0.2 新增項目見 CHANGELOG）：所有腳本與場景可載入、資料完整性（34 棋子／6 文明／24 關）、六角距離與找路、商店機率總和 100% 與牌池（外族 4 費永不出現）、經濟／利息／出售、XP 與等級表、購買與金幣不為負、三合一與三星上限、上場人數上限、羈絆同名只計一次、文明修正實際影響數值、星級倍率、遠征扣血公式（含浮點誤差）、結算順序（死亡不觸發鹿角人恢復）、通關／未完成判定、人類免費刷新券、商店鎖定、戰鬥可重現、單位不重疊、**所有主動技能都會在實戰中施放並產生效果**、存讀檔一致、六個文明各打一整局。

## 4. 匯出

在編輯器：「專案 → 匯出」，已預先建立以下設定（`export_presets.cfg`）：

| 預設 | 狀態 |
|---|---|
| **Windows Desktop** | 可直接匯出成單一 `SixTribes.exe`（資料已內嵌）。第一次需在匯出視窗按「管理匯出範本 → 下載並安裝」。 |
| Android | 已設定套件名稱 `com.sixtribes.expedition`、橫向、arm64；需在「編輯器設定 → 匯出 → Android」設定 Android SDK 與 debug keystore 後才能匯出。 |
| iOS | 已設定 Bundle ID；需在 macOS + Xcode 並填入 Apple Team ID 才能匯出。 |
| Linux（自動驗證用） | 用於在 Linux 上自動驗證匯出流程。 |

**自動發布**：推送 `v` 開頭的標籤（例如 `git tag v0.2.0 && git push origin v0.2.0`），GitHub 會自動跑檢查、匯出 Windows 版並建立 Release。每次推送到 `main` 也會自動跑 `tools/check.sh`，結果顯示在 Actions 頁面與 README 上方的徽章。

命令列匯出 Windows 版：
```bash
godot --headless --path . --export-release "Windows Desktop" build/windows/SixTribes.exe
```

專案沒有使用任何外掛、原生擴充或平台專屬 API；觸控透過「觸控模擬滑鼠」與滑鼠共用同一套操作，介面以 1280×720 為基準並自動延展到各種橫向比例（已測 16:9 與 20:9）。

## 5. 調整數值與美術

所有平衡數值都在 `data/`，改完重新執行即可，不必改程式：

| 檔案 | 內容 |
|---|---|
| `game_config.json` | 經濟與利息門檻／上限、XP 表、商店機率、星級倍率、稀有度基礎屬性、職業修正、戰鬥常數、**防禦公式（defense）**、**索敵參數（targeting）**、**備戰秒數（rounds.prep_seconds）**、**播放加速（battle_playback）**、**自動補位開關（board.auto_fill）**、敵方羈絆開關 |
| `units.json` | 24 棋子的種族／費用／類型／職業／射程／魔力與技能參數；`special_units` 為第一回合的教學弱敵（固定屬性） |
| `civs.json` | 6 文明的 Buff／Debuff（以效果碼描述，文字可直接改） |
| `traits.json` | 種族／職業／類型羈絆門檻與效果 |
| `stages.json` | 24 關敵軍清單、星級、站位、亂數種子 |

改完建議跑一次 `tools/check` 與 `balance_sim.gd` 看難度曲線。

**美術替換**：把圖片放到 `assets/units/<棋子ID>/star1.png`、`star2.png`、`star3.png`（例如 `assets/units/ELF1/star1.png`），遊戲會自動改用圖片；沒有圖片的棋子維持幾何占位圖，不會出錯。建議透明底、正方形、512×512。

## 6. 存檔位置

- Windows：`%APPDATA%\Godot\app_userdata\六族遠征\save_v1.json`
- Android／iOS：App 私有資料夾

每次進入備戰與每次操作後自動存檔；主選單「繼續遠征」可接續。遠征結束（通關／失敗）後存檔自動清除。
